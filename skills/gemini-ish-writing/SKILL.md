# 日本語ライティング＆推敲スキル

日本語の文章（ドキュメント、説明文、チャット文面など種類を問わず）を作成・推敲する際は、このスキルの基準に従う。まとまった文章やファイルを作成した場合は、最後に付属の Lint スクリプトで検証・修正する。

## 執筆時の5原則

1. **語彙レベル（レジスター）を統一する**
   - 技術文書やエンジニア間の連絡では、定着している技術用語・カタカナ語・漢語をそのまま使う。
   - わかりやすさを優先するあまり、曖昧な日常語・俗語・比喩に言い換えない。
2. **結論ファースト・構造化**
   - 冒頭の1〜2文で結論・決定事項を言い切る。
   - 「事実（確認したこと）」「推測・懸念」「相手に確認したいこと」を混ぜずに分けて書く。
3. **架空の創作・メタ解説をしない**
   - ユーザーから与えられていない日時・ファイル名・数値・エラーコードを勝手に創作して補わない（テンプレートなら `[対象の処理名]` 等のプレースホルダーを使う）。
   - 末尾に「この例で意識した点」「補足です」「他にも〜できます」といったメタ解説を付けない。
4. **目的に応じた文体と情報部分の圧縮**
   - 客観的な記録・定義として残す文書（設計書、仕様書、障害や調査の記録など）：フラットな常体（である調）。
   - 相手に向けて説明・案内・連絡する文章（比較解説、相談、チャット連絡など）：フラットなビジネス丁寧語（です・ます調）。「〜んですね」「〜かなと思います」等の砕けた口語を混ぜない。
   - 共通ルール：表のセル、カード、箇条書きで事実やスペックを並べる箇所では、冗長な語尾（「〜です」「〜ます」「〜である」）を省き、体言止めや短い言い切りで情報密度を上げる。
   - チャット貼付用の文面例に `**` などの Markdown 装飾を残さない。
5. **効果を具体的に書く**
   - 「効く」「強い」「良い」で済ませず、「処理時間が短縮される」「メモリ消費を抑えられる」のように何がどう改善するかを書く（ただし「キャッシュが効いている」など仕組みの動作自体を指す場合を除く）。

## 語彙変換リファレンス（NG日常語 → 推奨表現）

| 避ける表現（曖昧・口語・比喩） | 推奨する表現（技術用語・明確な語彙） |
| :--- | :--- |
| 同じ入れ物に入れる | 同じコンテキスト / ストア / オブジェクトにまとめる |
| 定型コード | ボイラープレート |
| 後から入れるほうが安い | 後から導入するほうがコストが低い |
| テストを厚くする / 同じ厚さで | 網羅度を上げる / メリハリをつける |
| 足を引っ張る | 足かせになる / 開発速度を低下させる |
| 接続を閉じ込める / 守る | 影響を局所化する / 障害の連鎖を遮断する |
| 中身に手を入れない | 該当箇所を変更しない |
| 検索に引っかかる | 検索にヒットする / 一致する |
| ざっくり / ぐっと / まっとうな / 空っぽ | 概略 / 大幅に / 妥当な / 空 |
| 〜なんですね / 〜かなと思います | 〜となります / 〜と考えます（または言い切る） |

## 文体の対比サンプル（Before / After）

### 例1：技術選定の説明（常体）
* **Before（日常語混在・冗長）**：
  > 更新頻度が違う値を同じ入れ物に入れると、無関係なコンポーネントまで再描画される。先に入れて外すよりも、後から入れるほうが安い。
* **After（語彙統一・簡潔）**：
  > 更新頻度の異なる値を同一コンテキストにまとめると、無関係なコンポーネントまで再描画される。初期導入後に撤去するより、必要になった時点で段階的に導入するほうがコストが低い。

### 例2：丁寧語での技術説明
* **Before（砕けた口語）**：
  > インメモリキャッシュはサーバーごとに別々のメモリに乗るんですね。再起動すると空っぽになりますし、Redisを入れる価値はぐっと上がります。
* **After（フラットなビジネス丁寧語）**：
  > インメモリキャッシュは各サーバーのメモリ上に保持されるため、再起動時にリセットされます。複数台構成でキャッシュを共有したい場合は、Redisの採用が合理的です。

## 推敲ワークフロー（必須）

まとまった文章やファイルを作成した後は、ユーザーに提示する前に以下のコマンドで Lint を実行し、`ERROR` が 0 件になるまで修正する（`WARN` も原則として解消する）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\.claude\skills\gemini-ish-writing\scripts\lint_ja.ps1" <出力ファイルパス>
```

標準入力からチェックする場合：

```powershell
@'
（生成した文章）
'@ | powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\.claude\skills\gemini-ish-writing\scripts\lint_ja.ps1" -Stdin
```
